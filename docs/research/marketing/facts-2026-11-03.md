# K7 campaign — primary-source facts sheet

Research date: **2026-11-03**. Every row below was read on the page cited; doc dates are the "last updated" the page itself displays. Where a doc does not state a thing, it says so rather than guessing. Marketing copy is deliberately absent.

Method note: several official pages are JS-rendered and return no body text to a plain fetch (Meta developer docs, YouTube Help, TikTok Business Help). Those were read through a text-extraction reader against the same URL. Anything I could not load at all is in the last section, not guessed.

| YouTube Shorts | **not stated in the doc** | "maximum resolution of 1080p" | **"up to 3 minutes long"** | **not stated in the doc** | [Get started creating YouTube Shorts](https://support.google.com/youtube/answer/10059070) | YouTube Help |

Codec/bitrate detail the docs do state — Reels: MOV/MP4, H.264 or HEVC, progressive, closed GOP, 4:2:0, 23–60 fps, VBR 25 Mbps max, AAC 128 kbps. Shorts: same source also notes the YPP Shorts threshold (1,000 subs + 10M qualified Shorts views/90 days). TikTok: MP4 (recommended)/WebM/MOV, H.264 (recommended)/H.265/VP8/VP9, 23–60 fps, chunks of 5–64 MB (final chunk up to 128 MB), 1–1000 chunks.

### A2. Safe zones / text-safe areas

**Not documented in any page I could load.** Meta's and TikTok's safe-zone guidance is not on the API reference or Help pages above, and TikTok's ad-spec article is dead: `ads.tiktok.com/help/article/tiktok-video-ad-specifications` now redirects and renders "The article you are looking for no longer exists or failed to load." ### A3. Ads vs organic lengths

The docs I could load do **not** publish a separate ad-length table. What is documented is the organic/API ceiling: TikTok's 3/5/10-minute creator tiers with a hard 10-minute developer cap, and Reels' 15-minute API ceiling versus Stories' 60 s. Treat "ads are shorter than organic" as unverified.

## B. API capabilities

| Question | Answer in the doc | URL |

| Rate limit | **Contradictory inside one doc.** Guide text: "Instagram accounts are limited to **100** API-published posts within a 24-hour moving period. Carousels count as a single post." Constraints worth knowing for automation: images are **JPEG only**, "Filters are not supported", "Shopping tags are not supported", caption max 2200 chars / 30 hashtags / 20 @tags, and "Music tagging is only available for original audio."

### B2. TikTok Content Posting API

- **Direct Post** (`/v2/post/publish/video/init/`) publishes straight to the profile; **Upload** is the inbox/draft path. Direct Post requires the `video.publish` scope, "Your app must be approved for the `video.publish` scope", and the user must have authorized it. ([Get Started – Direct Post](https://developers.tiktok.com/doc/content-posting-api-get-started), updated Aug 4 2026)
- **The audit rule, verbatim:** "All content posted by unaudited clients will be restricted to private viewing mode. Once you have successfully tested your integration, to lift the restrictions on content visibility, your API client must undergo an audit." ([same](https://developers.tiktok.com/doc/content-posting-api-get-started))
- You must call Query Creator Info first; the response carries `max_video_post_duration_sec` (the example shows 300).
- Limits: 10 min max via API, 4 GB max, plus the chunk rules in A1. Rate limits: **not stated in the doc**.

## C. Web / owned channel

### C1. Core Web Vitals

| Metric | "Good" threshold | Measures |
|---|---|---|
| LCP | "should occur within **2.5 seconds**" | loading |
| INP | "**200 milliseconds** or less" | interactivity |
| CLS | "**0.1** or less" | visual stability |

Measured at the **75th percentile** of page loads, "segmented across mobile and desktop devices"; a page passes only if it meets all three at p75. All three are lifecycle status **Stable**. ([Web Vitals](https://web.dev/articles/vitals), last updated Oct 31 2024)

### C2. PWA installability (Chrome)

Criteria for `beforeinstallprompt` + in-browser install promotion: not already installed; user engagement heuristic (**clicked the page at least once**, and **spent at least 30 seconds** viewing); served over HTTPS; manifest with `short_name` or `name`, `icons` "must include a 192px and a 512px icon", `start_url`, `display` one of `fullscreen`/`standalone`/`minimal-ui`/`window-controls-overlay`, and `prefer_related_applications` absent or `false`. **No service-worker requirement appears in the criteria.** ([What does it take to be installable?](https://web.dev/articles/install-criteria), last updated 2024-09-19)

### C3. Search Essentials + product rich results

Three categories: **Technical requirements**, **Spam policies**, **Key best practices**. Plus the caveat that meeting all of them "doesn't mean that Google will crawl, index, or serve its content", and that appearing "doesn't cost any money". ([Google Search Essentials](https://developers.google.com/search/docs/essentials), last updated 2025-12-10)

Product snippet eligibility (`Product` markup): requires `name` **and** "either `review` or `aggregateRating` or `offers`". Technical limit: "product rich results only support pages that focus on a single product (or multiple variants of the same product)" — so K7 needs one page per product, not a catalogue page. For merchant listing, `priceCurrency` is "required for merchant listing experiences" though only recommended for snippets; `price` requires a currency, and JS-generated markup "can make Shopping crawls less frequent and less reliable". ([Product snippet](https://developers.google.com/search/docs/appearance/structured-data/product-snippet), last updated 2026-09-08; [Merchant listing](https://developers.google.com/search/docs/appearance/structured-data/merchant-listing))

### C4. `.dev` TLD

Real technical constraint, confirmed by Google Registry: "The .dev top-level domain is included on the **HSTS preload list**, making **HTTPS required** on all connections to .dev websites and pages without needing individual HSTS registration or configuration." ([.dev — Google Registry](https://get.dev/), redirects to registry.google/domains/dev/) No SEO-specific constraint is stated on that page.

## D. Ad policy landmines

### D1. Music copyright — ads vs organic

TikTok is explicit and this is the strongest finding in the sheet: "**Businesses cannot use the general music library for commercial usage.** Businesses should instead use the Commercial Music Library for all commercial TikTok activities, including: Organic content, including a duet, react, or stitch with user videos; Video ads; Branded content." The library is "a pre-cleared global music library of 1 million songs… free for businesses to use", and the doc adds that if you use "original sound from other users or other licensed sounds in your organic or paid content, consult your legal team". ([About the Commercial Music Library](https://ads.tiktok.com/resources/help/article/commercial-music-library?lang=en), last updated July 2025; terms at [tiktok.com/legal](https://www.tiktok.com/legal/page/global/commercial-music-library-user-terms/en))

**Meta equivalent: not verified** — see last section.

### D2. Hardware claims: trademark, comparative, "no subscription"

The governing TikTok pages exist and are indexed, but I did not retrieve clause text, so I am citing location rather than quoting: [TikTok Advertising Policies](https://ads.tiktok.com/resources/help/article/tiktok-advertising-policies?lang=en) (last updated August 2025) fans out to [Intellectual Property Infringement](https://ads.tiktok.com/resources/help/article/tiktok-ads-policy-intellectual-property-infringement?lang=en) (the page that would govern third-party marks — "cassette", "Walkman", "Spotify"), [Misleading and false content](https://ads.tiktok.com/resources/help/article/tiktok-ads-policy-misleading-and-false-content?lang=en) and [Deceptive practices](https://ads.tiktok.com/resources/help/article/tiktok-ads-policy-deceptive-practices?lang=en) (the pages that would govern unsubstantiated "no subscription" or "better than X" claims).

### D3. EU rules

**Not verified.** I did not retrieve GDPR, ePrivacy or DSA article text within budget. The one EU-adjacent duty I can state from an official doc is Google's, not the advertiser's: consent-mode enforcement is tied to Google's [EU user consent policy](https://www.google.com/about/company/user-consent-policy/), with the two v2 parameters above. Do not let the plan assert a DSA advertiser obligation without checking [Regulation (EU) 2022/2065](https://eur-lex.europa.eu/eli/reg/2022/2065/oj) — the ad-transparency duties in Art. 26 sit on platforms, not advertisers, but that needs confirming in the text.

## Conflicts / things I could not verify

**Official docs that contradict common blog advice (all confirmed on-page):**

1. **YouTube quota model has changed.** The calculator now allocates **100 `search.list` calls/day and 100 `videos.insert` calls/day as separate buckets at 1 unit each**, plus 10,000 units/day for everything else. The widely repeated "`search.list` = 100 units, `videos.insert` = 1600 units, 10,000/day shared" is no longer what the page says.
2. **YouTube's private-upload rule is gone.** The insert reference now states unverified projects are **not** restricted to private viewing. Every "your API uploads will be private until you pass an audit" post is stale; audits now gate *quota increases*.
3. **Instagram's own doc contradicts itself** on publishing limits: 100 posts/24h in the guide prose, 50/24h in the carousel section of the same page. Plan against the lower number and confirm with `GET /<IG_ID>/content_publishing_limit`.
4. **PWA install criteria no longer list a service worker.** Most guides still do. Current criteria are HTTPS + manifest fields + engagement heuristic only.
5. **Shorts are 3 minutes**, not 60 seconds, and **Reels accept 15-minute uploads via API** even though consumer uploads are shorter.
6. **TikTok's ad-spec article is dead** — `tiktok-video-ad-specifications` 404s. Any safe-zone or ad-spec table sourced from it should be re-captured.

**Could not verify (URL checked, no usable text):**

- **Meta safe zones and Meta ad specs** — `facebook.com/business/ads-guide` and the Reels ad spec pages did not render.
- **Meta music in ads / "business account music library is limited"** — I found no official Meta page stating it. TikTok's equivalent is confirmed above; Meta's is an assumption until sourced.
- **Meta Conversions API dedup rule** — [deduplicate-pixel-and-server-events](https://developers.facebook.com/docs/marketing-api/conversions-api/deduplicate-pixel-and-server-events) loaded but truncated before the rule.

- **GDPR / ePrivacy / DSA clause text** — EUR-Lex not retrieved.
- **Instagram/Meta explicit app-review workflow** — access levels are documented; a review-required statement was not found on the pages read.
- **TikTok Content Posting rate limits** — not stated in the docs read.
